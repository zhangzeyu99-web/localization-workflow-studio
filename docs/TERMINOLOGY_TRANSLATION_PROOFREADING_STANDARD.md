# 术语翻译校对规范

## 定义

术语翻译校对规范用于处理这类任务：已有一版或多版译文交付，用户提供新的术语表、项目 brief、历史交付或校对要求，需要对指定语言列做术语一致性校对。

它不是重新自由翻译，也不是只跑格式检查。目标是用项目 brief、当前术语表、历史已验收交付和模型能力校对既有译文，并输出可追溯的 QA 摘要。

## 输入识别

- 项目上下文：brief、历史说明、项目名、题材、UI/公告/语言表类型。
- 术语来源：用户本次指定的最新术语表优先；在线术语表必须在任务开始时导出并记录 revision/hash，不得默认复用旧本地副本。
- 待校对译文：既有交付文件，不从空白重新生成，除非用户明确要求。
- 目标语言：只处理用户指定语言；未指定时按文件已有目标列和用户上下文确认，不凭空补语言。

## 术语处理规则

- 术语表交付列只保留一个主译，不写 `A / B` 组合译法。
- 不新增“补充变体列”；动词、名词、系统名等变体交给模型在正文语境中判断。
- 正文 QA 不强制逐字等于术语表主译；应检查主译是否被合理继承，语境变体是否自然且不漂移。
- 同一中文词同时有动词和名词用法时，术语表使用更通用、简短、适合游戏 UI 的主译；正文按句子语境调整词性。
- 用户明确要求保护的列，例如“不动英文列”，必须设为只读。
- `主角/角色名/人物名/英雄名/怪物名/BOSS/NPC` 等命名实体分类属于强制术语；正文仍可做自然语法衔接，但必须能回读确认主译已被继承。

## 标准流程

1. 建立任务快照：记录输入文件、输出目录、目标语言、术语表 revision/hash 和模型/API 配置；过程文件放 `_work/`，最终目录只放成品和 QA 摘要。飞书导出的 XLSX 若 worksheet dimension 低报为 `A1`，读取器必须重置维度后再扫描真实数据区。
2. 读取并对齐数据：校验源文列、ID、目标语言列、行数和未请求列保护。
3. 术语命中检索：每条源文做最长词优先命中，提供命中术语、目标语主译、项目 brief 和历史译法给模型。
4. 基础语义校对：重点检查术语命中行、结构 QA 风险行和长文本行；日常任务默认不做全量逐句审校。
5. 安全门禁：空译文、中文残留、乱码、U+FFFD、连续问号乱码、占位符、HTML/富文本标签、数字、日期、单位、范围和换行格式必须保留；`cache-lint` 必须用本次术语快照重新计算命中，缓存命中与快照不一致直接阻断。
6. 二次纠偏审计：对模型建议修改做回看，阻断过度术语化、语义变窄、普通词误改成系统名、UI 不自然等问题。
7. 读回验证：从最终 xlsx/docx 重新读取，不只相信内存状态；hard blocker 为 0 才能声明交付。
8. 输出交付：最终目录只保留成品文件和 `QA摘要.xlsx`。

## 深度逐句校对

用户明确触发深度逐句校对时，执行 `docs/DEEP_LINE_PROOFREADING_SUBAGENT_WORKFLOW.md`：

- 主控负责分包、确定性 QA、二次纠偏、写回和交付判断。
- subagent 只负责逐句审校建议，不直接修改 workbook/docx。
- 高风险行全量审校，低风险行抽样，除非用户要求全量逐句。
- QA 摘要记录触发条件、审校行数、建议修改数、最终应用数、回退数和 hard blocker 数。

## 最终回复要求

- 明确结构 QA 是否完成，hard blocker 数是多少。
- 明确是否启用深度逐句校对；如启用，说明建议修改数、回退数和最终保留修改数。
- 明确是否使用外部机翻；默认应说明未使用 Google/外部机翻。
- 提供最终交付目录和 QA 摘要路径。

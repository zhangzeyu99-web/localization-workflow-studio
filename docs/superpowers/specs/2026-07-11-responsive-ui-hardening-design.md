# 本地化工作台响应式 UI 收口设计

## 目标

在不改变现有配色、页面结构和业务流程的前提下，系统修复桌面中等宽度、低高度窗口和移动端中的裁切、断行、横向溢出、入口缺失与低对比度问题。

本次设计面向重复操作的本地化工作台。优先级依次为：功能入口完整、信息可读、布局稳定、视觉一致。

## 已确认问题

1. 桌面侧栏使用纵向 Flex 布局时，两个快捷入口会从约 56px 被压缩到约 40px，说明文字超出按钮后被 `overflow: hidden` 裁切。
2. `1024px` 视口中，交付列表固定使用三列，内容区横向溢出约 85px，并带动主区域出现横向滚动条。
3. 交付状态和翻译历史状态徽标允许换行，导致“可交付”“已交付”“已通过”显示为两行或逐字竖排。
4. “返回项目概览”等命令按钮允许文本换行，在中等宽度下高度从 36px 跳到约 50px。
5. `980px` 以下隐藏侧栏快捷入口，而项目总览没有快速任务入口，移动端用户无法进入快速任务。
6. 移动端项目页签容器宽约 351px，内容宽约 452px；隐藏滚动条后，后部页签不可见且缺少可滚动提示。
7. 翻译历史表在移动端被压缩到容器宽度，日期、表头、状态和操作逐字断行。
8. 空术语表在移动端没有稳定最小宽度，列头被压成单字列。
9. 多处 11-12px 次要文字使用 `#7b8791`，白底对比度约 3.67:1，不满足普通小字号文字的可读性目标。

## 设计原则

- 保留当前白色、浅灰和青绿色工作台风格，不重新设计主题。
- 命令按钮和状态徽标不换行；容器不足时由布局换列或换行，而不是压缩控件文字。
- 宽表格保留表格语义，并通过明确的横向浏览承载，不把每个单元格压成竖排。
- 移动端必须保留原始翻译、公告翻译和快速任务三个主要入口。
- 桌面宽屏保持现有信息密度；响应式变化只在空间不足时触发。

## 布局设计

### 侧栏

- 桌面快捷入口设置为不可压缩的 Flex 子项，并保留完整标题和说明。
- 项目列表继续承担可滚动区域，低高度窗口优先缩短项目列表，不缩短快捷入口。
- 移动端继续隐藏侧栏快捷入口，避免在横向项目列表下重复堆叠操作；快速任务入口改放到项目总览的主操作区。

### 项目总览入口

- 在“新翻译任务”“公告翻译”旁增加“快速任务”按钮，使用现有闪电图标和次级按钮样式。
- 三个入口在桌面同行显示，在窄屏使用现有 `row-actions` 自动换行。
- 新入口只切换到现有快速任务视图，不新建路由、不改变任务逻辑。

### 交付列表

- 宽内容区继续使用现有三列布局：任务、交付结论、进度与结果。
- 当交付列表容器小于或等于 820px 时切换为两列：第一行显示任务与结论，第二行让进度信息和操作占满整行。
- `980px` 以下继续使用现有单列卡片布局。
- 交付徽标保持单行并禁止收缩；任务标题允许省略号，不挤压徽标。
- 中等宽度下主内容区不得产生横向滚动条。

### 项目页签

- 桌面保持当前横向页签。
- `720px` 以下改成 `3 x 2` 网格，六个页签全部可见。
- 激活态继续使用青绿色下划线/边框，但网格行列的边界不应造成双重重边。
- 页签文本保持单行，点击目标不低于 40px。

### 表格

- 翻译历史表增加滚动容器；移动端表格设置 680px 的最小宽度，避免表头和状态逐字断行。
- 术语表和译文归档继续使用现有滚动容器；为空时也应用稳定最小宽度。
- 表格内部状态徽标保持单行，操作链接横向排列。
- 不把历史记录改成卡片，避免扩大改动面和降低批量扫描效率。

### 文本和控件

- 通用 `.btn` 和 `.tag` 使用 `white-space: nowrap`；布局负责换行，控件内部不换行。
- 次要文字统一提升到至少 `#68747f`，白底对比度约 4.78:1。
- 保留当前字号、圆角和间距，不增加装饰性卡片或新颜色。

## 组件边界

- `ProjectOverview` 新增快速任务回调，只负责展示入口并调用回调。
- `main.tsx` 复用现有 `setView('quick')` 与状态文案，不复制快速任务启动逻辑。
- `TaskHistoryTable` 只增加语义清晰的滚动容器，不改变分页、下载或详情逻辑。
- 响应式规则集中在现有工作台样式文件中，避免在组件内写视口判断。
- 后端接口、任务数据、交付逻辑和归档逻辑不变。

## 验收标准

### 桌面与中等宽度

- `1920 x 1080`：现有宽屏密度不退化。
- `1280 x 720`：侧栏两个快捷入口标题和说明完整可见。
- `1024 x 768`：交付页面无主区域横向滚动；所有状态徽标单行；返回按钮单行。

### 移动端

- `390 x 844`：总览可直接进入快速任务。
- 六个项目页签同时可见并形成 `3 x 2` 网格。
- 翻译历史、术语和归档表可横向浏览，表头、状态和操作不逐字竖排。
- 正式翻译、公告翻译和快速任务页面无内容重叠，固定操作栏不遮挡当前操作。

### 可访问性

- 所有可见交互目标尺寸至少 24px；主要按钮维持现有 36px 以上高度。
- 键盘焦点样式继续可见。
- 状态文案仍通过现有 `role=status` 和 `aria-live=polite` 宣告。
- 次要小字号文本对比度达到普通文字可读性目标。

## 验证方式

1. 运行前端生产构建和现有前端测试。
2. 使用应用内浏览器逐页检查总览、元信息、术语、翻译、QA、归档、交付、正式翻译、公告和快速任务。
3. 在 `1920 x 1080`、`1280 x 720`、`1024 x 768`、`390 x 844` 四个视口保存截图。
4. 程序化检查主区域横向溢出、异常高状态徽标、按钮断行和小于 24px 的可见交互目标。
5. 对比本轮修复前截图，确认原问题消失且宽屏布局未退化。

## 非目标

- 不调整后端、任务状态或交付规则。
- 不重做配色、导航层级或页面信息架构。
- 不把所有表格改成移动端卡片。
- 不新增动画、主题或视觉装饰。

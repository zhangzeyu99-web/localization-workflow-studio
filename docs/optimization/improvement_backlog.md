# 工作台改进建议队列

## 使用规则

这里记录从验证集失败、用户反馈、失败轨迹库中沉淀出来的改进建议。它不是愿望清单，只收“能降低返工或提升稳定性”的项。

原则：

1. 建议可以由人写，也可以后续由模型辅助总结。
2. 建议不能直接改正式 prompt、harness 或代码。
3. 必须人工确认后才进入开发。
4. 完成后必须补验证 case 或更新已有 case。
5. 同类失败出现 2 次，优先级上调。

## 状态定义

| 状态 | 含义 |
|---|---|
| 待评估 | 已记录，尚未决定是否做 |
| 已采纳 | 确认要做，进入开发计划 |
| 已拒绝 | 不做，并保留原因 |
| 已完成 | 已修复并通过验证 |

## I-001 上传错误统一人话提示

- 来源：F-202606-001；validation_set/008_cloud_deployment_smoke.md
- 类型：错误提示 / 流程
- 优先级：P0
- 建议内容：所有上传入口统一错误解析。413 显示“文件超过上传上限”；完整语言表误传显示“请上传到语言表步骤”；后端 HTML 错误只展示摘要。
- 预期收益：用户知道下一步怎么处理，不再看到 Failed fetch 或 HTML。
- 风险：需要确保详细日志仍可供开发排查。
- 验证方式：用超限文件、错误格式文件、正常文件分别上传。
- 状态：待评估

## I-002 前端禁止展示 traceback 和服务器命令

- 来源：F-202606-002
- 类型：错误提示 / 安全
- 优先级：P0
- 建议内容：建立统一 `UserFacingError` 展示层；前端只显示标题、原因、下一步；traceback、命令、服务器路径写入后台日志或诊断 artifact。
- 预期收益：降低用户困惑和信息泄露风险。
- 风险：开发排查需要多一步打开日志。
- 验证方式：故意触发公告术语提取失败，检查页面不出现 Python traceback。
- 状态：待评估

## I-003 交付页只展示真实可下载产物

- 来源：F-202606-003
- 类型：交付 / UI
- 优先级：P0
- 建议内容：交付页加载时校验 artifact 文件存在；不存在则显示“交付文件缺失，请重新生成”，不展示死链接。
- 预期收益：避免用户点击下载后才发现 Not Found。
- 风险：校验文件存在会增加一次后端检查。
- 验证方式：运行 001、002、006、007 并逐个点击下载。
- 状态：待评估

## I-004 完整语言表防误导入规则固化

- 来源：F-202606-004；validation_set/003_glossary_candidate_from_language_table.md
- 类型：流程 / 数据质量
- 优先级：P0
- 建议内容：将完整语言表识别规则固化为后端共用函数，术语导入、公告约束、新翻译 STEP4/STEP5 都复用同一判断。
- 预期收益：避免同一文件在不同入口表现不一致。
- 风险：真实术语大表可能被误判，需要模板字段兜底。
- 验证方式：完整语言表被拦截，术语模板可导入。
- 状态：待评估

## I-005 术语导入后以实际列表刷新为准

- 来源：F-202606-005
- 类型：数据刷新 / UI
- 优先级：P0
- 建议内容：术语导入或候选确认后，不只更新状态文案，必须重新拉取宽表数据；如果实际数量为 0，提示“未写入术语”。
- 预期收益：避免“显示成功但列表为空”。
- 风险：大表刷新需要分页，避免一次性渲染过多。
- 验证方式：确认候选入库后回到术语表，搜索该术语。
- 状态：待评估

## I-006 公告完成态与新任务入口分离

- 来源：F-202606-006；validation_set/006_announcement_txt_delivery.md
- 类型：流程 / UI
- 优先级：P0
- 建议内容：公告任务已交付后，项目概览卡片按钮改为“查看结果”；侧边“公告翻译”或顶部入口默认创建新任务，历史任务从列表进入。
- 预期收益：用户能区分继续旧任务和开始新任务。
- 风险：需要处理用户仍想回看旧任务的入口。
- 验证方式：完成公告任务后点击公告入口，应进入新任务；点击历史任务应回到旧任务。
- 状态：待评估

## I-007 hard block 恢复路径标准化

- 来源：F-202606-007；validation_set/007_hard_block_recovery.md
- 类型：QA / 交付
- 优先级：P0
- 建议内容：所有 QA failed 页面统一展示问题数量、问题列表、下载问题报告、上传修复文件、重新 QA、生成问题交付。
- 预期收益：hard block 不再是 deadend。
- 风险：允许问题交付时必须明确标注风险，避免误当最终通过。
- 验证方式：构造 100 行以上 hard block 样本，修复前后各跑一次。
- 状态：待评估

## I-008 线上版本一致性检查前置

- 来源：F-202606-008；validation_set/008_cloud_deployment_smoke.md
- 类型：部署 / 运维
- 优先级：P0
- 建议内容：线上页面加载时可显示后端版本；部署检查必须验证前端 dist 与后端 `/api/version` 匹配。
- 预期收益：快速发现“前端新版、后端旧版”。
- 风险：需要定义前端构建时注入版本的方式。
- 验证方式：部署后运行 `/api/version` 和页面版本检查。
- 状态：待评估

## I-009 删除项目流程兜底

- 来源：F-202606-009
- 类型：项目管理 / 清理
- 优先级：P1
- 建议内容：删除项目前后都重新同步项目列表；当前项目被删除后自动切到最近项目或空态；失败提示具体原因。
- 预期收益：测试项目能清掉，用户不会被残留项目困住。
- 风险：真实项目删除不可逆，二次确认必须保留。
- 验证方式：创建测试项目，长按删除，确认列表和当前项目状态正常。
- 状态：待评估

## I-010 AI 启动前 provider 配置检查

- 来源：F-202606-010
- 类型：AI 流程 / 设置
- 优先级：P0
- 建议内容：AI 分析、AI 翻译、公告 AI 翻译、快速任务启动前统一检查 provider；未配置时按钮引导到设置，不创建失败任务。
- 预期收益：减少无意义失败 run。
- 风险：测试项目允许 mock 的规则要保留清晰边界。
- 验证方式：清空 API key 后尝试启动 AI 流程，检查是否被前置拦截。
- 状态：待评估

## I-011 验证失败自动生成改进建议的轻量规则

- 来源：验证集机制
- 类型：自我沉淀 / 流程
- 优先级：P1
- 建议内容：先不做自动模型总结；人工跑 case 失败时，必须在失败库新增记录，并在本文件新增或更新建议。
- 预期收益：形成最小自我进化闭环。
- 风险：依赖人工纪律，需要在 PR/提交前检查。
- 验证方式：任意失败 case 必须能追溯到 failure_log 和 backlog。
- 状态：待评估

## I-012 验证集逐步自动化

- 来源：validation_set/README.md
- 类型：测试 / 自动化
- 优先级：P2
- 建议内容：先挑 3 个最稳定 case 写脚本：线上 smoke、下载 Not Found 检查、完整语言表防误导入。
- 预期收益：减少人工回归成本。
- 风险：过早自动化复杂 UI 会维护成本高。
- 验证方式：脚本在本地和线上 URL 都能运行。
- 状态：待评估

# 007 hard block 恢复

## 任务目标

验证 QA 出现 hard block 后，流程不是死路；用户能看懂问题、下载问题交付、修复后重新交付。

## 输入文件

- 至少 100 行的语言表或译文表。
- 人为加入 5-10 行明显问题，例如禁用词、变量丢失、标签丢失或中文残留。

## 操作路径

1. 上传测试表并进入 QA。
2. 运行 QA。
3. 确认 QA failed。
4. 查看 hard block 数量和问题详情。
5. 下载问题交付或 changes 文件。
6. 修复问题后重新上传或使用修复入口。
7. 重跑 QA。
8. 生成最终交付。

## 通过标准

- hard block 数量不重复计数。
- failed 状态仍有可操作入口。
- 用户能知道为什么不能直接交付。
- 支持下载问题报告或问题交付。
- 修复后可以重新 QA 和交付。
- 带问题强制交付时，交付摘要必须带 `delivered_with_issues: true` 标记（翻译、合并、公告三类交付一致）；干净交付为 `false`。

## 失败信号

- failed 后按钮全部不可用。
- 页面只显示 `hard blockers must be fixed`，没有问题列表。
- hard block 同一问题被重复计数。
- 修复后仍卡在旧状态。

## 清理方式

删除测试项目，保留本次问题记录到失败轨迹库。

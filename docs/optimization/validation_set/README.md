# 工作台固定验证集

## 目的

这套验证集用于防回退：每次修流程、改 UI、改后端接口或准备部署前，都按这里的 case 检查一遍。它不是测试报告，也不是功能说明，而是“真实用户会怎么跑”的最小样本集。

## 使用规则

1. 每个 case 必须能由人工照着步骤跑。
2. 每个 case 必须有明确通过标准和失败信号。
3. 如果真实用户又遇到同类问题，优先补充这里，而不是只在聊天里说明。
4. case 可以逐步自动化，但第一版先保证流程定义清楚。
5. 验证失败后，必须同步登记到 `docs/optimization/failure_log.md`，并在 `docs/optimization/improvement_backlog.md` 形成改进建议。

## 统一判定

### 通过

- 用户能按步骤走完。
- 页面状态和按钮含义能看懂。
- 产物能下载，不返回 `Not Found`。
- 出错时能看到人话提示和下一步。
- 测试项目能清理。

### 失败

- 页面只显示 `Failed to fetch`、`Internal Server Error` 或 traceback。
- 任务状态显示已完成但无法下载。
- 流程进入 deadend，没有继续、修复、跳过或取消入口。
- 数据写入了错误位置，例如完整语言表直接进入项目术语库。
- 测试项目或任务删除失败。

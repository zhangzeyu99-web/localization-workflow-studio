The problem this workflow solves

AI translation is useful for game localization, but raw model output is not a delivery artifact. Most game teams still ship language tables in Excel, and those tables contain IDs, UI strings, placeholders, tags, line breaks, naming conventions, and product-specific terminology.

The risk is not just a bad sentence. The bigger risk is losing traceability: nobody can prove which prompt, glossary, source row, provider output, or QA check produced the final workbook.

Core rule: treat AI as a worker. The source workbook, glossary, workpack IDs, QA gates, and reviewer decisions remain the source of truth.

Recommended workflow

  1. Define the project profile. Capture genre, audience, tone, text types, target language, forbidden translations, and UI constraints.
  2. Normalize the glossary. Keep canonical terms, acceptable alternatives, categories, and reviewer notes in a structured table.
  3. Import the Excel language table. Preserve stable row IDs, source text, target columns, placeholders, tags, and line-break shape.
  4. Generate a workpack. Convert workbook rows into batchable JSONL input with fingerprints and context snapshots.
  5. Translate with a provider. Ask GPT or Claude for strict line protocol output, not free-form prose.
  6. Apply output defensively. Reject missing IDs, duplicate IDs, reordered rows, placeholder drift, tag drift, and stale input fingerprints.
  7. Run localization QA. Check terminology, placeholders, line breaks, readability, UI length hints, and project-specific rules.
  8. Review and archive. Store reviewed translations only after QA passes, then produce final workbook artifacts.

What should be in a workpack

A workpack is the bridge between an Excel workbook and an AI provider. It should be strict enough that model output can be verified before anything touches the delivery workbook.

FieldWhy it matters
idStable row identity. Output must match the requested ID set exactly.
sourceOriginal text for translation and review.
text_typeUI button, item name, tooltip, system message, quest text, or marketing copy.
placeholdersTokens such as {count}, %s, or player-name variables that must survive translation.
tagsRich text or markup that cannot be broken.
glossary_hitsTerms the provider and reviewer must respect.
line_break_shapeWhether newlines are intentional and must be preserved.
input_fingerprintPrevents stale model output from being applied after the source row changes.

QA gates that should block delivery

Localization QA should run before final workbook export. The checks below are small, but they catch the failures that make AI-assisted translation unsafe for production.

  • Placeholder mismatch: missing, duplicated, or changed runtime variables.
  • Tag mismatch: broken markup, missing closing tags, or reordered UI tags.
  • Line-break drift: model output collapses or adds line breaks in UI-sensitive text.
  • Glossary conflict: canonical game terms are ignored or translated inconsistently.
  • Length risk: UI labels are too long for buttons, menus, skill cards, or shop items.
  • Mock output: test providers or missing-provider fallbacks are blocked from real delivery.
  • Fingerprint mismatch: output was generated from an older source row.
Do not archive unreviewed model output. A translation memory should store reviewed decisions, not raw provider responses.

How Localization Workflow Studio maps to this

Localization Workflow Studio is built around this exact workflow:

  • Project profile and prompt snapshots for repeatable context.
  • Glossary extraction and review tables for term consistency.
  • Excel workpack generation with IDs, placeholders, tags, line breaks, glossary hits, and fingerprints.
  • Provider adapters for GPT and Claude, with mock output blocked from delivery.
  • Rule-based QA for workbook safety before final export.
  • Translation archive and delivery artifacts after review.

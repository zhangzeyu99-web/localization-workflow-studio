# v1.7.2 公告文本与回填可靠性修复说明

发布日期：2026-08-07

## 修复内容

- 公告 TXT 输入同时支持 UTF-8、UTF-8 BOM 和 GB18030，不再因中文 Windows 文本编码报 `utf-8 codec can't decode`。
- 公告翻译中转表不再把超过 Excel 单元格 32,767 字符上限的句子适配 JSON 写成截断内容。
- 已经生成的旧版截断中转表可跳过损坏的可选句子适配数据，继续执行 QA、回填和产物生成，无需重新调用模型。
- 普通英文和印尼语术语允许自然单复数变化，例如 `Survivor` 可在句子中写成 `Survivors`。
- 游戏名、专名和显式 exact-match 术语继续严格匹配，`Legend of Mushroom` 不会接受 `Legend of Mushrooms`。
- 新生成的公告中转表保留术语分类和精确匹配元数据，避免把普通术语和游戏名使用同一种检查规则。

## 兼容性

- 不变更账号、角色、项目成员、注册和权限模型。
- 不迁移现有 SQLite、项目、上传文件、任务结果或外置 `settings.local.json`。
- 有账号包继续使用 `cloud/required`；无账号包继续锁定为可信公司内网 `cloud/off`。
- 旧公告任务可以在部署后直接重新执行校对回填，不需要重新翻译。
- 运维仍需解压到全新版本目录，复用版本目录外的 `LWS_DATA_ROOT` 与 `settings.local.json`，不能覆盖旧版本目录。

## 制品

```text
有账号-v1.7.2.zip
有账号-v1.7.2.zip.sha256
无账号-v1.7.2.zip
无账号-v1.7.2.zip.sha256
```

两个包必须来自同一个干净提交和同一份前端生产构建，并具有相同的 `version`、`git_sha_full` 与 `frontend_dist_sha256`。

## 发布验收

- 使用线上故障中转表验证旧版截断 JSON 可以直接读取，7种语言基础 QA 硬问题为 0。
- 回归测试覆盖超长单元格、新旧中转表、GB18030、普通术语复数及游戏名严格匹配。
- 后端、内嵌工作流、Ruff、Python 编译、TypeScript、Vite 和双 profile Playwright 通过。
- 两个 ZIP 的包内成员哈希、包外 SHA-256、manifest、敏感文件扫描和全新解压 cloud 模式检查通过。

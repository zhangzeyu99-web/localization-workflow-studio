# v1.6.1 统一版发布说明

发布日期：2026-07-21

## 发布状态与边界

- v1.6.1 统一为一个源码提交、一个 production frontend dist 和一个 universal ZIP；`local/off` 与 `cloud/required` 是同一版本的两种生产运行配置，不是两条产品线。
- 本文定义发布候选的验收合同，不代表 GitHub tag、Release、远端推送或线上部署已经完成。推送、发布和部署是需要单独授权并分别验收的后续动作。
- v1.6.0 是统一前的历史账号线候选；v1.6.1 取代其双产品线定位，但不改写旧版本当时的测试或部署事实。

## 制品身份

唯一制品名为：

```text
localization-workflow-studio-v1.6.1-g<sha12>-universal.zip
localization-workflow-studio-v1.6.1-g<sha12>-universal.zip.sha256
```

包内 `PACKAGE_MANIFEST.json` 使用 schema v2，必须读回并核对：

- `artifact_kind=universal`、`version=1.6.1`、`source_state=clean_git_commit`。
- `git_sha` 为 12 位短 SHA，`git_sha_full` 为同一 clean commit 的完整 SHA。
- `supported_runtime_profiles` 精确为 `local-off` 与 `cloud-required`。
- `frontend_dist_sha256` 与唯一 production frontend dist 一致。
- `runtime_payload_sha256` 与解压后的运行载荷一致。
- `contains_settings_local=false`、`excluded_runtime_data=true`。

包外 `.sha256` 必须匹配 ZIP 的 SHA-256；包内 `SHA256SUMS.txt`、成员 allowlist、凭据扫描、manifest identity 与双 tree digest 都必须通过 readback。包内安装说明固定为 `DEPLOY_README.zh-CN.md`，profile 模板固定为 `deploy/profiles/local-off.env.example` 和 `deploy/profiles/cloud-required.env.example`。

## 两个生产运行配置

### 本地 `local/off`

- `LWS_DEPLOYMENT_MODE=local`、`LWS_AUTH_MODE=off`。
- Windows 解压包使用 `start-workbench.cmd` 或 `scripts/start-workbench.ps1`；包模式只启动一个 Uvicorn 实例并由后端服务已构建前端。
- 无需登录且不创建账号；操作身份为 synthetic local admin。登录、注册、用户管理和项目成员管理入口隐藏，设置入口可见。
- deployment check 必须读到 `local/off/local-off`，匿名业务 API 可用；stability flow、runtime Playwright、临时项目删除和 active jobs 清理全部通过。

### 线上 `cloud/required`

- `LWS_DEPLOYMENT_MODE=cloud`、`LWS_AUTH_MODE=required`；使用 `deploy/profiles/cloud-required.env.example`。
- 未登录业务 API 必须返回 401；登录、角色、项目成员、自助注册和首次登录改密保留。
- HTTPS 下浏览器会话必须使用 Secure `lws_session` cookie；deployment check 的 `anonymous_projects`、登录后上传可读性、stability flow、runtime Playwright 和清理检查全部通过。
- `cloud/off` 是配置错误，必须在启动阶段 fail-closed；不得把它宣传或验收为第三个生产配置。

`local/required` 只用于测试或开发，不属于生产发布矩阵。

## 数据与会话保证

- `LWS_DATA_ROOT` 始终位于 release 目录之外；通用包不携带数据库、上传文件、任务产物、日志、凭据或 `settings.local.json`。
- 在 `local/off` 与 `cloud/required` 之间切换不删除、不重建、不破坏项目、业务数据或文件，也不做破坏性迁移。
- profile 切换会清除不兼容的服务端会话和浏览器会话状态；切换前的旧会话不得在新 profile 中恢复有效。

## 验收门禁

Source gates 至少包括：

```powershell
python -m pytest -q
python -m compileall -q backend scripts check.py
python -m ruff check backend scripts check.py
npm run build --prefix frontend
npm run e2e --prefix frontend
npm run e2e:auth --prefix frontend
```

production frontend 只构建一次；随后使用真实打包命令：

```powershell
python scripts/build_release_package.py --output-dir release_archives --no-rebuild-frontend
```

同一个 `universal-release` artifact 必须分别完成 Windows extracted `local-off` smoke 与 Ubuntu TLS extracted `cloud-required` smoke。两边必须读回相同的 artifact ID、manifest `version`/`git_sha`、`frontend_dist_sha256`、`runtime_payload_sha256` 和 outer ZIP SHA；任一 profile 身份错误、`cloud/off` 未拒绝、业务流程失败、数据切换失败或清理不完整都阻断发布。

## 发布授权

本地验证、提交、创建 tag、推送 GitHub、创建 GitHub Release 和线上部署是独立动作。只有对应动作获得授权且 readback 成功后，才能记录“已推送”“已发布”或“已上线”；本文和本地通过的门禁本身不构成这些事实。

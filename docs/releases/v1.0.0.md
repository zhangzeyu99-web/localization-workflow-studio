# Localization Workflow Studio v1.0.0

发布日期：2026-06-10

## 版本定位

`v1.0.0` 是工作台第一个正式版本。当前版本以“本地工作台 + 后端编排 + 已配置 AI Provider”为生产边界，不依赖 Codex/Agent 才能运行。

## 正式能力范围

- 语言包翻译：项目资料、AI 分析、语言表、术语候选、目标语言、后台模型翻译、自动校对、交付。
- QA / 译文归档：已有译文可直接校对，也可在明确确认后跳过 QA 归档。
- 多语言资产：EN / KR / JP 等语言宽表展示、搜索、分页、导入导出。
- 公告翻译：项目内公告任务、术语提取、译文反查、翻译准备、AI 翻译/导入、QA 回填、交付包。
- 快速任务：项目内三步翻译/校对入口，任务记录可追溯。
- 长文本稳定编排：后端拆批、限流、断点续跑、失败恢复、交付。

## Provider 边界

正式模型路径只接受 OpenAI/GPT-compatible 或 Claude。项目明确禁止 Google Translate、`deep_translator`、`googletrans`、浏览器机翻和在线机翻聚合器。

## 验收基线

发布前本地通过：

```powershell
python -m pytest -q
python -m compileall -q backend workflow
python -m ruff check backend/app backend/tests --select E9,F
cd frontend; npm run build
cd frontend; npm run e2e -- --workers=1
rg -n -i "deep_translator|googletrans|GoogleTranslator|translate\.google|google translate|Google Translate|GOOGLE_TRANSLATE|google_trans" backend workflow frontend --glob "!frontend/node_modules/**"
```

## 已知边界

- 没有 API key 时，项目分析只能生成本地规则草稿，不声称完成 AI 资料分析。
- Project Brief Markdown 只有符合结构化 brief 形态时才主导分析；普通需求文档只作为补充资料。
- 技术仓库 `workflow/glossary` 和 `workflow/localization` 仍保留内置接口，方便后续同步上游更新。

# Localization Workflow Studio v1.1.0

发布日期：2026-07-09

## 版本定位

`v1.1.0` 是一次 MINOR 发布：新增用户可见的多人并发能力（不同项目可同时跑任务），并完成一轮前端结构/性能/视觉优化。不改变翻译/QA/交付业务语义和 API 输出契约；不引入账号/权限体系；仍然是单实例单 uvicorn worker、不共享 SQLite 给多 worker。

## 改动摘要

### 多人并发（后端，M1-M5）

- SQLite 开启 WAL 日志模式；修复 run/公告 metadata 的读-改-写竞态（`db.merge_run_metadata` 原子合并，覆盖 runs/QA/多语言/公告约 15 处调用点）。
- 任务锁从"全产品一把"演进为项目级 `long_text:{project_id}` lease：不同项目的翻译/QA/公告/模型修复任务可以真正并行；同项目内仍严格串行（断点续跑、manifest、harness 文件读改写的保证不变）。
- 新增全局并发上限 `max_concurrent_ai_jobs`（默认 2，可调 1-4）；409 拒绝区分"项目忙"（`project_busy`，提示"该项目正在执行任务（{任务描述}），请等它完成或先取消"）与"容量满"（`capacity`，提示"工作台已有 {N} 个任务在跑（上限 {M}），请稍后再试"）。
- 新增 `GET /api/system/active-jobs`：返回当前所有活跃任务（lease 名、任务类型、项目名、开始时间）。
- 新增进程级共享限流器：同一 provider/API key 的并发任务共享同一份 RPM/TPM 预算，不会叠加超发。
- 任务启动时快照 `settings.local.json` 并全程使用，运行中他人改配置不影响已启动任务。
- `project_harness.json`、`improvement_suggestions.json` 的读-改-写加文件锁，防止 API 线程与后台任务的编辑窗口互踩。
- 项目存在活跃任务时删除请求被 409 拒绝，不再与任务的文件 IO 赛跑。
- 修复 `cancel_translation_run` 的 lease 名不匹配问题。
- 新增 `scripts/concurrency_smoke.py`：隔离实例上的并发冒烟脚本，验证两项目并行完成、`active-jobs` 曾同时显示两任务、无 `database is locked`、第三项目在容量满时被拒绝。

### 前端优化（F1-F4，纯 UI/结构，不改业务语义和 API 契约）

- **F1 提示语人话化**：新增集中文案层 `uiText.ts`；去除状态枚举/字段名/文件路径/UUID/STEP 编号等内部标识直出；原生 `alert`/`confirm` 替换为应用内 `ConfirmModal`。
- **F2 结构拆分**：`main.tsx`（原 ~2500 行）和 `TranslationWizard.tsx`（原 ~2100 行）拆分为 modal、项目总览、按域 hooks、按步骤 wizard 文件，行为不变。
- **F3 性能**：5 套轮询收拢到共享 hooks（`document.hidden` 检查、in-flight 去重、`AbortController`）；run 活跃时暂停项目快照轮询；热路径组件加 memo；三大向导视图懒加载；run 历史/项目动态列表分页。
- **F4 视觉规范**：`styles.css` 新增 design token 层（色板、间距、圆角、字号），高频色值收敛到变量，卡片选择器收敛到公共基类，新增 ~640px 小屏断点。

### 部署与文档收尾（M5）

- `docs/CLOUD_DEPLOYMENT.md`：替换"单实例单任务"约束段为新并发模型说明；保留"单实例单 worker、不共享 SQLite 给多 worker"约束；故障判断表新增"多人同时跑任务混乱"行的排查方法。
- `docs/STABILITY_TEST_LIST.md`：新增 7 项多人并发验收项（并行翻译、同项目互斥、容量拒绝、活跃任务可见性、重启恢复、settings 隔离、删除防护）。
- `docs/FEATURE_MATRIX.md`：新增多人并发功能行及其绑定测试。
- 版本号从 `1.0.4`（`backend/app/main.py`/`frontend/package.json` 此前已漂移到 `1.0.3`）统一升级到 `1.1.0`：`VERSION`、`backend/app/main.py`、`frontend/package.json`、`frontend/package-lock.json`、`README.md`、`CHANGELOG.md`、本文件。

## Provider 边界（沿用 v1.0.0）

正式模型路径只接受 OpenAI/GPT-compatible 或 Claude。项目明确禁止 Google Translate、`deep_translator`、`googletrans`、浏览器机翻和在线机翻聚合器。

## 已知边界

- 不做账号/权限/登录体系；操作留痕仅为可选的浏览器本地昵称（请求头 `X-Operator`），只记录不校验。
- 仍然固定单实例单 uvicorn worker；不支持多 worker 共享同一份 SQLite 数据库。
- 全局并发上限默认 2，是 provider 预算/内存/SQLite 写压的保护阈值，不建议无脑调到 4 以上。

# v1.6.4 游戏名术语约束修复发布说明

发布日期：2026-07-24

## 发布内容

- 完整语言表会同时读取 `CN`、`Chinese_PRC` 与 `Chinese_PRC.N` 中文源文列；同一条英文译名可约束多个中文游戏名。
- 公告翻译默认接入已确认项目术语；本次人工编辑、项目术语和已选语言表不再被旧译文归档覆盖。
- 重叠术语按实际出现位置执行长词优先：标题中的完整游戏名会压制内部短词，但正文独立出现的玩家称呼仍保留对应译法。
- `term_hits` 成为强制约束，整句模板不能绕过；错误译文不会再通过追加正确术语后被 QA 放行。
- v1.6.3 旧公告任务若缺少术语来源标记，会按当前“项目术语 > 语言表 > QA 归档”重建缓存；人工导入与 AI 补充仍保留。
- 正式语言表 QA 使用 Unicode 词边界判断术语；“游戏名 / 固定译名 / exact”按精确术语阻断变形，普通多词术语仍允许正常单复数。
- 同时交付有账号与无账号两个云端部署包，两者来自同一个干净提交和同一份前端生产构建。

## 真实缺陷回归

本版本覆盖以下生产问题：

```text
项目名：Legend of Mushroom
中文别名：菇勇者传说
错误产出：Shroomie Legendary
正确术语：Legend of Mushroom
```

验收要求：

- `Chinese_PRC.1` 中的“菇勇者传说”能命中 `Legend of Mushroom`。
- “菇勇者 → Shroomie”和“传说 → Legendary”不能拆分覆盖完整游戏名。
- 项目术语和任务内人工编辑优先于同源旧归档。
- 错误译文保持 `term_missing` 严重问题，不能被自动拼接后清零。
- 已缓存错译的 v1.6.3 旧任务原地重跑时，lookup、prepare 和 translate 全链路恢复 `Legend of Mushroom`。

## 制品

```text
有账号-v1.6.4.zip
有账号-v1.6.4.zip.sha256
无账号-v1.6.4.zip
无账号-v1.6.4.zip.sha256
```

有账号包是 universal 制品，云端默认使用 `cloud/required`，保留登录、自助注册、管理员用户管理、角色和项目成员权限。

无账号包是专用 profile 制品，运行配置锁定为可信公司内网 `cloud/off`；不提供登录、注册、用户、角色或项目成员管理。

两个包必须具有相同的 `version`、`git_sha_full` 和 `frontend_dist_sha256`，并分别通过包内成员哈希、包外 SHA-256、敏感文件扫描和全新目录解压实跑。

## 运维升级

- 解压到全新版本目录，不能覆盖旧目录。
- 继续使用版本目录外的 `LWS_DATA_ROOT` 与 `settings.local.json`。
- 从包内 `PACKAGE_MANIFEST.json` 读取 `git_sha` 设置 `LWS_GIT_SHA`。
- 使用单 worker 后端，原子切换 `current` 后重启。
- 本地生成制品不代表已经部署线上；上线后仍需从真实域名复核 `/api/version`、`/api/health`、缓存响应头和静态资源摘要。

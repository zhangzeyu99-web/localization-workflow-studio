本轮结合代码、自动化测试和当前真实页面抽查。手工后台启动受环境策略限制，后改用项目已有的隔离 E2E 托管服务，完成总览、QA、交付和快速任务三步的页面采样；不是全站逐屏可访问性审计。测试只使用临时数据目录，不使用业务数据。上一轮未提交改动保持原样，不自动提交、推送或发布。

检查基线：本地 `master`，HEAD `09c0c8d`，工作树产品版本为 `1.7.3`，包含上一轮尚未提交的工作流同步改动。本轮没有重新同步两个参考仓库，也没有直接修改 `workflow/localization` 或 `workflow/glossary`；以下结论是本地候选的验收，不是远端或线上状态结论。

## 用户流程

| 步骤 | 当前流程与健康状况 |
| --- | --- |
| 1. 项目入口 | 总览进入正式翻译、公告或快速任务；运行中恢复、停止未交付时继续/放弃、终态新建。显式任务 ID 的入口具备隔离，旧无 ID 接口保留兼容行为；不建议重做统一任务模型。 |
| 2. 正式翻译 | 资料 → 分析 → 术语 → 输入判定 → 目标语言/翻译 → QA/修复 → 交付。已有译文可以直接 QA，避免重译。 |
| 3. 快速任务 | 输入 → 可选参考 → 目标与启动，成功后原位生成并读回交付。本轮补齐识别失败重试和同会话换输入的上传/识别响应隔离。 |
| 4. 公告 | 资料 → 约束 → 语言 → 术语 → 反查 → 准备 → 翻译 → QA回填 → 交付。A 将提取/导入成功改为留页，核对后明确继续，不减少步骤或质量检查。 |
| 5. QA与修复 | 翻译内含检查；修复后重新 QA。本轮多语言批量 QA 改为采用当前 run 的通过状态，不再按输出文件存在免检。 |
| 6. 归档导入 | 来源 → 设置 → 差异预览 → 明确提交 → 批次与项目读回。本轮将样例改为风险和变化优先，保护与事务不变。 |
| 7. 交付与下一任务 | 保留任务级交付、历史查看和新任务清空；快速任务下载读回不可省略。公告和快速任务不回写译文归档，lookup 保留软参考。 |

## 第一阶段实施范围与验收标准

1. 快速任务输入检查恢复：识别失败后可以复用已上传文件重试，不重复上传；每次换输入隔离响应，旧文件结果不能覆盖新文件；三步和后续 QA 不变。
2. 多语言 QA 真值：失败或待处理任务即使已有输出文件，也不能跳过 QA；当前确实通过的任务保持幂等，不被旧成功结果掩盖新失败。复用旧任务 ID 续跑时，按既有入队时间而非创建时间识别当前执行；普通备注或其他元数据更新不改变执行先后。前端启动结果也采用当前 run，而不是优先打开历史 QA。
3. 归档差异样例：优先展示冲突、受保护、清空、停用、更新和新增；不变/跳过排后；只改变样例顺序，不改变提交计划、计数或 token 校验。

验证顺序：定向回归复现 → 最小修复 → 定向测试 → 后端完整测试与前端构建 → 可用时执行浏览器全流程回归及截图读回。未完成的层级单独列出，不以编译成功代替流程验收。

## 保留的质量门槛

- 导入仍需分析与确认；受保护覆盖、快照范围确认、版本/校验和检查、原子提交与回滚冲突检查不变。
- 翻译保留源行、ID、占位符、程序标签、数字/条件、目标语言和写回读回检查。
- 术语人工确认和修复后 QA 不变；不把测试 provider 的通过当成真实翻译语义质量证明。
- 运行队列完成不等于 QA 通过，存在输出文件也不等于 QA 通过。
- 保留现有显式带问题交付契约，不静默扩大或收紧业务权限。

### 交互方案 A：公告术语结果留页

现状：第 4 步提取/导入/保存 → 服务端标记第 5 步 → 页面自动跳到反查 → 要核对术语需返回第 4 步 → 保存后又跳转。问题在推进时机，而不是九步过多。

建议：提取成功留在第 4 步展示结果；无编辑时“确认并继续”，有编辑时“保存并继续”，保存成功再去第 5 步。刷新恢复待确认结果；服务端业务进度和当前查看步骤分开，不粗暴回退服务端状态。普通轮询不得覆盖未保存草稿；零术语结果允许明确继续，不等于尚未提取；保存失败保留内容。保留术语权威优先级、AI 复查和反查。

### 交互方案 B：在现有术语表完成待复核

现状：强制覆盖会产生 `imported/pending/confirmed=False` 的活动术语；正常列表、宽表及导出只展示已确认词条。已有按 ID 编辑确认接口，但缺少找到待复核记录的入口；候选术语表并非同一类数据，不能拿候选确认替代。

建议：导入结果提示“X 条待复核”并跳至现有术语表的待复核筛选；支持编辑并确认或稍后处理，不新增独立页面。确认沿用现有人工维护语义；保存增加原子版本条件，其他人已修改则提示重载，不先 GET 再盲写。运营/管理员按既有 assets:curate 权限写，成员只读。没有逐条恢复旧值能力时不伪造按钮，继续使用已有整批回滚。

译文的 pending 仍可作为 lookup 软参考，S07 只补来源提示；本方案不扩展为译文批量确认系统。现有列表截图只证明布局与入口，所选合成项目当前无术语记录；“隐藏待复核”结论来自代码和专项测试，不将空项目截图冒充复现。

### 交互方案 C：当前交付在前，历史折叠

现状：当前修复后的待生成交付和旧带问题交付平铺，需要用户自行辨认。另有单语言文件路径覆盖风险，由 S05 独立修复，不等待界面方案确认。

### 顺序、验证与回退

1. **阶段一：正确性小修。** S01–S08 逐项红测试 → 最小修复 → 定向回归；完成后冻结改动，再执行组合后的后端全量、前端完整 E2E、账号 E2E、生产构建、diff 和编码门禁。
2. **阶段二：用户选择 A/B/C。** 推荐三项，彼此可独立接受。建议先 B（恢复入口可达），再 A（减少往返），最后 C（依赖底层版本已稳定）。未确认不实施；P04/P05 不夹带。
3. **阶段三：逐项实施已确认方案。** 每项都有真实页面截图与回归测试；不把本轮动线示意当成已实现 UI。出现失败回退该项交互补丁，保留正确性修复和业务数据，不用 Git 硬重置或删除归档回退。
4. **阶段四：组合验收与升级报告。** 逐项标明已实现、已验收、待选和剩余风险；数据库兼容与已有历史下载单独验收。所需版本、提交、推送与部署包发布另需授权，当前不自动执行。

验收矩阵：三类任务的 T1 交付 → T2 全新、运行中恢复、停止/继续/放弃、刷新与切项目隔离；TXT/表格/公告；结构 QA 失败/修复通过/显式带问题交付；归档预览/提交/读回失败重试/并发修改/权限；新旧下载哈希与历史查看隔离。结构和流程测试不替代真实模型逐句语义质量评估。
